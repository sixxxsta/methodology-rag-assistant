# Документирование проекта (ГОСТ 19, учебный контекст)

## Зачем документация в учебном проекте

Документация нужна команде для согласования понимания, а не только для отчёта. Минимальный набор:

1. **Техническое задание / постановка** — цель, ограничения, критерии приёмки.
2. **Описание архитектуры** — компоненты, потоки данных.
3. **Руководство пользователя** — как пользоваться результатом.
4. **Руководство разработчика** — как собрать и запустить.

## ГОСТ 19 (ЕСПД) — ориентиры

- Единообразие терминов и обозначений.
- Структура: введение, назначение, требования, описание, приложения.
- Версионирование документов вместе с кодом.

## Практические советы

- Храните документы рядом с кодом (`docs/`).
- Обновляйте README при каждом значимом изменении API.
- Используйте диаграммы (C4, sequence) для сложных потоков.
- Ведите **changelog** или release notes.

## Роли в документировании

Назначьте ответственного за актуальность docs на спринт — ротация роли снижает «забывание».
